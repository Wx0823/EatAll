# EatAll 项目经验

仅记录项目内、证据支持的可复用经验。它不是模型训练、全局记忆或跨项目规则。后续按 WORKFLOW 的改进闭环更新；不要求每轮新增条目。

## EA-L001：名称不同不代表仓库隔离

- 场景：在新项目中分析参考、创建文档或提交代码之前。
- 现象：本聊天先前工作目录位于搜打撤仓库子目录，视频分析被误提交至 MiaoSK，随后按用户要求回退。新项目名称没有隔离父仓库。
- 原因（已确认）：未将用户项目边界与真实 Git 根目录、origin 一起核验。
- 措施：EatAll 使用 `E:\吃吃吃`；每次任务先核实 Git 根目录与 origin；旧聊天路径仍存在时使用明确的新绝对路径。应用目录显示和磁盘配置分开验证，不把保存文件当作当前窗口已生效。
- 证据：本聊天的误提交/回退记录；EatAll 独立初始化提交 `426144b0fb11f516b9df12edf8664701b5625226`。本条为历史摘要，不冒充另存的原始日志。
- 本轮验证：开始任务在 `E:\吃吃吃` 执行，origin 为 EatAll，fetch 后本地与 origin/main 均为上述提交。本轮在独立目录完成预检，根目录与远程符合要求；未执行错误目录拦截测试，不代表所有未来入口已验证。
- 落实：AGENTS.md 项目边界、WORKFLOW 第一步和程序角色的提交检查。
- 状态：本次隔离已验证；应用界面关联的缓存刷新仍需单独确认。责任：主理人；复核：自查。

## EA-L002：技能校验先核对 Python 依赖和编码

- 日期/场景：2026-09-29，使用 Skill Creator 的 quick_validate.py 校验中文技能。
- 现象：捆绑 Python 未安装 PyYAML；临时安装后，校验器默认按 GBK 读取 UTF-8 文件，报 UnicodeDecodeError。
- 原因（已确认）：校验器依赖外部 yaml 模块，且使用未指定编码的 read_text；当前 Windows 默认文本编码与技能文件不一致。
- 措施：只向系统临时目录安装 PyYAML 6.0.3，通过临时 sys.path 载入；以 `python -X utf8` 执行校验器，不改变技能文件编码或修改系统 Python。
- 验证：五个角色均返回 `True / Skill is valid!`，入口 Markdown 引用断链0项；原错误与修复后输出保留在本轮工具记录。校验只证明文件结构与引用，不证明实际游戏能力。
- 落实：测试角色增加中文技能工具的环境预检；复用现有校验器，不为本次问题另造验证框架。
- 状态：本次校验已通过；其他机器未验证。责任：主理人；复核：自查。

## EA-L003：并行方案先统一坐标、暂停语义和概念图用途

- 日期/场景：2026-09-29，系统、关卡、程序、美术并行制定首版框架。
- 现象：技术初稿采用左下原点/y向上，系统稿采用左上/y向下；系统初稿的暂停/撤销/重开合并表述可能误读成暂停回退。概念图v1将食物/身体与地形重叠，v2改善重叠但遗漏棋盘内出口。
- 原因（已确认）：坐标契约尚未在并行起草前固定；不同命令被合并表述；生成概念图不能保证规则几何或所有功能元素。
- 措施：技术稿以EA-R0.1左上原点/x右y下为唯一来源；暂停显示当前已结算状态，不回退，撤销/重开分别定义。概念图只作为风格提案，记录遗漏，不按它制作碰撞或宣称可解。
- 验证：主理人与QA角色逐稿核对坐标；系统作者修订后QA复读暂停语义；主理人实际看过v1/v2并保留生成记录。详见 design/technical/implementation-plan.md、production/qa/framework-review.md、design/art/concepts/generation-notes.md。未运行游戏或触控验收。
- 落实：程序技能增加跨角色坐标/命令契约核对；概念图与生产数据边界保留在美术稿和总提案。以后优先交接共用契约，再并行展开，减少合稿返工。
- 状态：文案冲突已修正，实际行为待原型；v2功能元素遗漏仍存在且仅限气质提案用途。尚无可比耗时数据，不宣称效率提升比例。责任：主理人和相关作者。

## EA-L004：真实输入、像素坐标与本地构建需要端到端验证

- 日期：2026-09-29，v0.1实施与交付。
- 输入现象/原因（确认）：原先关闭触摸转鼠标，鼠标按钮测试不能证明Android按钮可点；原生触摸链补测后又发现输入回调同步移出节点导致can_process错误。启用仿真，轮盘忽略仿真鼠标，按钮回调deferred。独立QA原生Input.parse_input_event补测140/0、日志干净；主理人另增加返回键默认退出配置与断言，定向141/0。不能用直接Viewport触摸转发冒充系统仿真链。
- 画面现象/原因（确认）：可变字体用字符串轴键时仍是Thin；头部在归一化坐标上放大draw transform导致AA羽化一起变大，禁用AA又产生锯齿。读取支持轴后用整数OpenType wght键；头部改像素几何、旋转/镜像保留单位缩放；短屏底部控件按宽度计算。最终5张真实图形截图复看通过。落实到美术像素AA与多宽度检查，概念图不替代实际画面。
- 工具现象/原因（确认）：单独重命名Godot console包装会找不到同名主程序；Adoptium移动API403；Android首导出只给空配置错误，经4.5.1引擎源码定位缺ETC2/ASTC导入开关。分别使用配对可执行文件、固定版本校验下载、开启Android纹理导入；本机自包含设置隔离，不修改其他项目。
- 实际验证：tools/build.ps1导出Android/Windows成功、APK v2/v3签名验证、Windows成品启动exit0；候选APK在Android14模拟器安装启动。证据见production/qa/v0.1/delivery.md及独立测试/美术报告。工具脚本实际执行，非仅代码检查。
- 遗留：模拟器FeedShaderGLES3报错但棋盘正常，当前只确认未阻断二维UI，根因未验证；真机手感/GPU覆盖/性能未测。源码检查后的最终返回键修正包未重新覆盖当前有人推进的模拟器试玩，明确区分候选安装与最终验签。
- 状态：输入/画面/构建上述问题已验证修复；模拟器兼容错误为未解决项。责任：主理人；独立QA复核输入、美术复核截图，打包主理人自查。未量化效率提升。
- 同步补充：首次push连接重置，`git -c http.version=HTTP/1.1 push origin main`单次重试成功，远程确认0049b5e；只是本次传输绕过，不能认定网络根治。不改TLS校验，不因本地commit就报已上传。

## EA-L005：可玩与清楚不等于兑现美术效果图

- 验证：1090项功能检查无失败；独立视觉QA复看首页、06/12/07、失败、短屏、四向L/U及5个运动帧，最终有保留通过本次美术返工。报告production/qa/v0.2/art-review.md，不能省略成完全复制概念。
- 落实：美术技能新增效果图对照验收及镜像锚点检查。遗留：程序身体比插画规整、上下头朝向表达、短屏密关细节和真机表现仍有改进空间；没有宣称这些已解决。主理人负责交付质量，QA独立复核，未量化效率提升。

## EA-L006：手感须检查完整时间轴，动作须检查真实绘制

- 日期/现象：2026-09-30，用户指出控制不丝滑、缺少喜感。旧输入长按首个连走间隔490ms、随后320ms；新喜感动作实际转弯吃糖时又出现10条triangulation failed，尽管脚本退出0。
- 原因（确认）：旧_process在busy中提前return，动画期间不扣长按时钟，等待时间被叠加；逐格smoothstep与下落重置又制造停走。身体半径波纹在紧弯处让单个闭合外轮廓自交，整体polygon剖分失败；增长起点重复尾坐标增加零长切线。
- 措施：长按时钟包含动画，160ms步长/时间统一，格边继续采样当前方向而不补过期队列；整体下落连续加速。喜感reaction独立计时，暂停冻结、撤销清空。身体每层用显式三角形带mesh绘制、清除重复中心点、保持跨帧mesh引用，避免自交轮廓剖分而不压日志。
- 验证：旧/新同一10ms走廊采样490/320→160ms；1/60秒采样为166.7ms，未宣称绝对毫秒精度。73项独立动作检查+1090原回归=1163/0；原生触摸图形原复现重新跑，完整日志无ERROR/WARNING，转角图完整。Android最终APK实际长按L1三步赢、L7重开后RURRD五步赢。证据production/qa/v0.3/motion-review.md、delivery.md、verification.txt及实图/录像。
- 落实：程序技能增加输入时间轴/长帧回归，QA技能增加图形日志与实际动态复跑；tools/test.ps1纳入test_motion。不是每轮增加一套冗余框架。
- 遗留/状态：上述调度和已复现几何问题已验证修复；喜感是否让玩家觉得好笑仍待用户试玩，真机操作/FPS及全部长体转角未覆盖。主理人负责整合，QA独立验证。没有量化整个团队工作效率收益。

### v0.4 同类反馈复发：目标平台动态性能漏测

- 2026-09-30用户再次录屏指出不流畅，并要求实际张嘴闭嘴。逐帧看315帧录屏，在5.70–7.23秒角色/轮盘经常133–167ms才改变一次；30FPS视频容器不能证明游戏30FPS。旧测试只覆盖固定delta和桌面录制，未测Android动态绘制，属于验收覆盖不足。
- 确认两项问题：每步丢弃跨帧时间余量使变delta见证序列在首步168ms后累计成184ms节奏；Android模拟器候选棋盘_draw约95–99ms，远超正常帧预算。没有复现“起步画面跳到未来逻辑格”假说，不将其写作确定原因。实际口型原先只是脸部缩放，不能满足此次明确张嘴要求。
- 连续优化归为本次事件：保留mesh与缩小采样、改native多层线、斑点stamp只降到约90/75ms，仍不通过；单身体颜色带mesh和静态Canvas缓存才降到约3ms。分段又确认静态网格AAcircle一次重绘约25ms，出口更新时也会重绘，进一步改复用点mesh/纹理。首次烘焙与持续绘制分开采样，保留失败尝试，不拿桌面2.52ms冒充Android性能。
- 时间轴保留正常帧余量，异常长帧最多一个新步；独立321项新检查+73项旧动作检查通过。实际闭嘴/半开/大开图册与目标食物坐标控制吞入口内、闭合和咀嚼；QA检查口型、undo缓存恢复、暂停冻结、长体紧弯与resize。
- 落实：程序/QA技能加入目标平台动态性能、初始资源/运动/空闲分开采样和变delta检查。最终实际运行结果见production/qa/v0.4/delivery.md及verification.txt；这些证据适用本机模拟器，不代表真实手机或用户主观接受。

## EA-L009：多语言验收要检查随包字体与实际设备语言

- 日期/现象：2026-09-30，新增简体、繁体和英文。独立QA首次1469项中1项失败：撤销↶（U+21B6）不在内置NotoSansSC字体中，Windows系统fallback使实画看似正常，不能证明Android可移植。
- 原因（确认）：旧文字按钮将图标字符与文案混合，依赖未随包提供的字体；这不是翻译编码损坏。
- 措施：去掉三语撤销文案的字符前缀，常驻/失败撤销按钮接入独立SVG；保留font.has_char断言，新增原生语言自称、方向符号和选中标记检查。集中三语目录，手动偏好与系统默认分离，旧存档新字段缺失/无效不丢进度；英文按表面空间缩字号。
- 验证：独立本地化1489/0、全部8套3094/0与29张真实桌面图；最终APK实际zh-CN默认、zh-TW/en-US应用系统语言自动、手动英文重启优先和动态英文HUD/撤销图标均通过。production/qa/v0.5.1保留首次失败及最终证据；测试结束恢复原Android语言配置，并比较进度/手/音效字段均不变。
- 落实：程序技能补目录/偏好/状态保留/字体检查，QA补旧存档、短屏、目标系统来源与环境恢复；本地化测试进入现有tools/test.ps1，不搭建另一套工具框架。
- 遗留/状态：本轮已复现缺字已修正并验证；三语功能/布局在本机桌面与Android模拟器通过，真实手机覆盖仍待验证。主理人整合，QA独立桌面验证；没有编造效率收益。
