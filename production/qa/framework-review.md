# EatAll 框架静态复核与后续验收计划

2026-09-29。结论：有保留，仅限方案一致性；不构成游戏运行通过或开发启动批准。

本轮程序职责作者自查 [技术提案](../../design/technical/implementation-plan.md)，并以QA职责只读交叉复核系统、关卡、主理人总稿，以及由美术角色初步回传、主理人整合的美术文档。技术稿不是独立QA验收对象；实际实现应由非实现作者执行独立验收。本轮无游戏代码、运行器、求解器或真机包，所有行为案例均为计划或人工推演。

## 审查对象与发现

| 对象 | 结果与范围 |
|---|---|
| [总提案](../../design/framework-proposal.md) | 已定竖屏/轮盘与候选规则、风格、Android/Godot分开；先单关输入闭环、3个代表关、再12关为相容阶段；概念图缺失不冒充实机验收 |
| [核心框架](../../design/systems/core-framework.md) EA-R0.1 | 区分用户确定的竖屏/轮盘与候选规则；输入、增长、自碰、外部支撑、逐格危险、落稳出口顺序明确 |
| [首章](../../design/levels/first-chapter.md) | A、B图坐标与人工动作表相容；A右3步、B右5步可在候选规则下逐步解释。其余10关仅简报，没有运行地图，不能宣称12关可解 |
| [技术提案](../../design/technical/implementation-plan.md) | 作者自查；主理人另行发现坐标与系统稿相反，已改为左上原点、y向下，初始身体至少2格且不覆盖出口。输入参数均为待试调值 |
| [美术方向](../../design/art/visual-direction.md) | 已复读主理人整合稿：主题与首章一致、四向轮盘/不遮挡棋盘/食物轮廓提示/出口两态符合规则；明确概念板非生产资产，v1重叠和v2缺出口已披露，未见新增范围冲突 |

已发现并处理/追踪：

1. 技术初稿采用y向上，系统和两关采用y向下。主理人交叉复核发现，技术稿已统一y向下；验证为文本对照，未证明序列化或游戏坐标实现正确。
2. 系统曾把动画期间暂停、撤销和重开同写为“恢复相应快照”，可能混淆暂停与撤回动作。已向系统作者回传并完成修订；复读系统稿确认与技术稿一致：暂停显示本回合已结算稳定/终局状态，撤销才回动作前。仅语义一致性通过，运行行为待测。
3. 主理人报告概念图出现可收集物与实体同格、身体叠平台。主理人随后报告v2改善重叠但缺少主画面出口。两版均是美术气质参考，不是符合网格规则的关卡数据或可导入生产资产；本QA未把图片当实机证据，需在正式资产和灰盒阶段重新对齐碰撞并补齐完整功能表达。此限制不阻止作为风格提案提交。

## 实现后的最小验收矩阵

全部项目当前状态：未运行。

| 领域 | 输入/场景 | 可观察预期及证据 |
|---|---|---|
| 增长与历史 | A图右一步再撤销 | 长度3→4→3，果实1→0→1；记录身体数组和画面 |
| 无效动作 | 出生反向、入实体、非旧尾自碰 | 状态与历史不变，仅反馈；比较完整快照 |
| 旧尾边界 | 头旁为本步腾空尾格，非180度反向 | 普通步可进；增长保留的占用格不可进，使用合法夹具分别构造 |
| 支撑 | B图第三、第四步；另测侧贴墙 | 第三步尾托住、第四步头接力；侧贴墙无托底须下落 |
| 重力收集 | 头随整体下落经过或停在未吃果实 | 果实与长度不变，计数与描边保持；再主动离开并进入才收集 |
| 危险优先 | 身体中段先碰刺；同一步有出口机会 | 每个下落格检测，任意身体触危即失败，不误报成功 |
| 出口 | 果实未清、尾进出口、下落经过出口 | 均不胜；全清且头落稳在出口才胜 |
| 原子撤销 | 有效动作后多格下落至失败再撤销 | 一次撤销回整个动作前，无半落状态；历史不会跨关 |
| 短拨 | 单次拨出/回中、恰在死区与吸附边界 | 明确方向触发1格，死区不走，不出现斜移/随机方向 |
| 连续输入 | 长按、忙碌时转向/松手、低帧率 | 节奏受间隔与完整回合限制，不积压补走，不因低帧率改变状态 |
| 中断 | 多指、通知/失焦、暂停恢复、动画中撤销/重开 | 无触点抢占和恢复后自走；暂停不退步，撤销不残留旧表现 |
| 进度保存 | 通关、重开、重新启动、模拟损坏 | 已通关不因重开丢失，重复成功幂等；损坏恢复不崩溃，隔离存档验证 |
| 关卡数据 | 坐标反向、重复果实ID、不稳定出生 | 明确拒绝并定位字段；不静默调整成另一张图 |
| 可解性 | 小图求解、预算超限、实际运行重放 | 记录有解/完整穷尽无解/未知；候选解逐步重放而非只看终点 |
| 分发 | 目标手机安装、冷启动、完整关循环 | 留包版本、设备、分辨率、录屏与已知限制；构建成功不能替代 |

轮盘验收必须用真机或明确标注的触屏设备，键盘回放只能检验规则，不代表方向吸附和拇指操作通过。方向识别、危险提示、实体/装饰区别及果实遮挡需要默认缩放截图和实际操作共同检查。

## 试玩与放行边界

提案可以提交用户审阅，不应声称12关成品已经完成。引擎与首发目标确认后先做一个灰盒关，把规则、轮盘、撤销和原生安装闭环跑通，再扩关。12关交付要求每关有有效地图、候选解和运行重放；真实玩家体验单独记录。没有真实参与者不得声称易懂、有趣或30—90秒目标已达成。

优先记录无意多走、方向误判、首次支撑误判、撤销原因、果实计数理解和卡关位置。用同设备、同关和同操作条件比较修改前后；样本有限要明说。没有数据不报效率百分比，不为每次试玩重复创建同类问题报告。
