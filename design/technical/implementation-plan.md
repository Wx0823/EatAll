# EatAll 技术实施提案

状态：设计提案，尚未启动游戏实现。2026-09-29。用户明确优先竖屏、虚拟轮盘控制方向；引擎、首发系统及具体实现范围待决定。玩法以 [系统规则](../systems/core-framework.md) 为唯一来源，本稿说明技术映射。

## 最小结构与执行顺序

建议单角色、固定侧视二维网格；12关、1主题、1角色为团队范围提议。程序拆为输入适配、纯规则推进、关卡数据、表现播放、局内历史、进度六个职责，不先搭建插件框架或复杂服务层。

规则推进只接受当前稳定状态和一个四向动作，输出新状态与有序事件；不依赖帧率、动画位置、刚体引擎或屏幕坐标。无效动作不改变局内状态、不产生撤销历史。一次有效动作的移动、吃果、增长、逐格下落和终局判定构成一个原子回合；表现按事件插值播放。事件顺序服从系统规则，动画速度不能改变解法。

身体以头到尾的有序整格坐标保存。下落整体平移，外部地形提供支撑；自身身体邻接不是支点。按2026-09-30用户修订EA-R0.2，主动移动或安全下落的头进入果实格即吃；下落增长记growth_pending，随后主动步最多展开1节，避免在整体平移中强插尾格。落下每格先检查危险与出界，胜利在落稳且无失败后检查。中段/尾部与果实可视觉重叠，不能以身体擦过代替头部吞食。

## 竖屏虚拟轮盘（首版历史方案，v0.5由十字键替代）

轮盘控制方向，不能变成连续自由位移。建议固定圆盘位于底部独立操作区，提供左右手位置切换；棋盘保持可见，顶部显示剩余果实，撤销和重开与轮盘不重叠。最终尺寸由美术和真机触达测试共同定稿。

以下数值均为试调起点，未经实测：

| 项目 | 建议行为 |
|---|---|
| 触摸归属 | 仅从轮盘有效区开始的第一个手指获得控制；第二个手指不抢方向。离开有效区仍保持该触点捕获，抬手/取消即解除 |
| 死区 | 距中心达到半径22%才激活；回到16%内归零，避免边缘抖动 |
| 四向吸附 | 取主轴方向；初次恰在45度边界不发动作，等方向明确；已选方向越过边界约10度再切向 |
| 首次指向 | 从中立进入明确方向，若规则与表现均就绪，立即尝试1格 |
| 长按 | 同方向首步后350ms开始重复，之后至少间隔180ms；实际间隔不短于完整回合播放时间 |
| 转向 | 就绪时有效切向立即尝试1格，并重置长按计时；180度反向仍按规则拒绝 |
| 动画期间 | 不缓存动作队列。只保留触点当前方向，播放结束重新采样；不补发错过的重复次数 |
| 释放 | 松手、回死区、触摸取消、失焦、暂停和终局都清空方向与重复计时；已开始的原子回合完成，不取消一半状态 |
| 无效方向 | 短促阻挡反馈，同一方向持续受阻时停止重复，须回中立或切向再尝试，避免震动刷屏 |

跨方向抖动时不连续触发。忙碌期间松手，结束后不得补走；忙碌期间转向，结束时最多执行一次当前有效方向，若当前方向与未释放的长按方向相同，仍遵守间隔。暂停恢复与切回前台必须重新触摸才能走。成功/失败页面不接收方向移动。

暂停时若表现未播完，取消表现并直接显示本回合已结算的稳定或终局状态；恢复后保持该状态并重新触摸，暂停本身不撤销回合。撤销与重开优先于轮盘：动画中点击时停止当前表现，回到规则已保存的稳定快照；清空轮盘状态，避免恢复后立即走一步。误触重开可用明确视觉反馈和充足间距控制，不默认增加频繁确认弹窗。桌面键盘仅作开发验证输入，不能替代触屏验收。

## 快照与存档

每个被接受的有效动作开始前保存完整稳定快照：关卡ID及数据版本、有序身体、剩余果实ID、局内状态和影响后续推进的其他状态。撤销恢复快照及HUD，失败允许撤销；重开回关卡初始态并清空历史。首版不含重做，除非以后批准。

无限撤销指无游戏次数限制。历史应保留本局所有有效动作，不能静默截断成固定步数；实现后测长局内存。必要时采用检查点加动作记录重建，不能更改用户可撤销范围。关卡结算后进入下一关会重置本局历史，返回已完成关按初始态重玩。

长期保存只保存关卡解锁、已通关和操作设置；中途局面跨会话恢复不是本次默认范围。进度原子写入、版本检查、损坏时保留备份并安全回退。测试使用隔离存档，不能覆盖用户正式记录。

## 关卡数据契约

采用可审查的文本数据格式，具体序列化和运行目录待引擎选择。以下字段是契约建议，关卡稿引用同一坐标约定后再冻结。

- `schemaVersion`、`rulesVersion`、`id`、主题标识；宽高为正整数。
- 坐标左上为原点，x向右、y向下；有效范围为0至宽/高减1，地图外为失败区，不自动生成隐形边墙。
- `terrain` 为实心地形格集合；`hazards` 为危险格集合；`fruit` 包含稳定ID和坐标；`exit` 一个格；`body` 从头到尾且相邻曼哈顿距离为1。
- 初始身体至少两格、不重复、不碰地形/危险、不出界；果实ID与位置唯一；地形、危险、果实、出口初始互斥；初始身体不覆盖果实或出口。美术装饰独立于碰撞数据。
- 初始局面必须稳定、有至少一颗果实，头不在出口；入口校验失败应报告关卡ID与字段，不悄悄纠正地图。
- 候选解保存方向序列、数据校验摘要与最终期望状态。编辑器显示坐标与运行器一致。

## 有限求解器验证

批准实现后，复用确定性规则推进提供有限搜索。状态键必须包括有序身体、剩余果实和growth_pending；相同头坐标不是相同状态。只搜索落稳状态，自动落下是单条动作边的一部分；无效动作不扩展，失败态不扩展。

首版使用广度优先搜索评估小关，建议单关上限20万状态或10秒（任一先到即停，阈值按实测调整），同时记录版本、时间、访问量和停止原因。找到解仅证明给定模型内可达；预算用尽标未知，不能标无解。只有完整耗尽可达图才可在该规则模型下判无解。最短步数只在单位成本主动动作与完整BFS层序条件成立时宣称。

求解器候选解必须在实际运行器重放；规则单测、独立人工推演和UI输入重放覆盖不同失误源，不能仅因求解器与游戏共用代码就宣称独立验证。首章不承诺唯一解。

## 两条技术路线

| 路线 | 适用与取舍 | 本项目建议 |
|---|---|---|
| Godot + GDScript，原生移动导出 | 采用二维节点承载表现，规则独立模块；需要准备目标平台导出工具链 | 优先候选：项目规模小、二维规则明确，先做一个可触控灰盒闭环再扩展内容 |
| Unity + C#，原生移动构建 | 同样可规则与表现分离；采用该路线需统一编辑器与构建模块，再建立测试入口 | 若后续已有Unity生产人员或明确依赖其现成管线，再选此路线 |

上述推荐为团队工程判断，不是性能实测。官方文档确认 Godot 提供 [Android导出流程](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_android.html)，其 [iOS导出](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_ios.html) 要求 macOS 与 Xcode；Unity提供 [Android构建](https://docs.unity3d.com/6000.0/Documentation/Manual/android-BuildProcess.html) 与 [iOS构建](https://docs.unity3d.com/6000.0/Documentation/Manual/iphone-BuildProcess.html) 文档。2026-09-29查阅。文档支持可用路线，不代表本机已具备工具链、签名或真机。

建议首个验收包优先Android竖屏；目标系统、具体引擎待用户选择。当前Windows环境不能被当作已可交付iOS的证据。批准后先盘点工具，不在提案阶段安装。第一关原型验收顺序：规则及回合重放 → 轮盘真机触达与误操作 → 撤销/重开 → 代表关可解性 → 扩展12关与美术 → 本地安装启动和完整通关。每步只扩展已获批范围。

本稿由程序职责编写并自查；不是独立QA对程序实现的验收。没有编写或运行游戏、没有求解器结果、没有真机输入数据、没有帧率或包体结论。后续验收计划见 [框架审查](../../production/qa/framework-review.md)。

## v0.3 当前输入与动作参数（2026-09-30）

用户反馈“操作现在一点都不丝滑”“表现也差点喜感”。本节取代上文初稿的350ms首重复、180ms续重复建议，作为当前实施契约；数值是程序调校，不是用户指定。

- `main.gd::MOVE_SECONDS = 0.16` 同时定义主动移动时间与同向长按起步间隔。时钟包含动画时间，动画完成后在同一帧重新采样轮盘，没有额外等待。持续移动为线性插值，不再每格重置平滑减速。离散规则仍走整格。
- 不保存方向动作队列；动画中只保存当前方向，边界最多执行一次。松手取消未执行方向；已接受的整格动作继续完成。长帧或长下落后不追补多个过期动作。
- 重力按完整下落距离加速播放，`FALL_ACCELERATION = 160`格/秒²，总时长为`sqrt(2 * 下落格数 / 加速度)`。逻辑仍逐格检查危险；表现按累计位移插值，不在每行之间停顿。
- 食物在主动移动75%位置开始咀嚼/碎屑/身体波纹；下落、落地、受阻和胜负反应独立计时，不延长输入锁定。胜负逻辑先确定、关闭轮盘，展示420ms现场反应后弹面板；这期间撤销/重开仍有效并取消旧面板。
- 暂停取消主移动动画、显示已结算状态，并冻结短时表现；恢复清空输入。撤销清空短时表现和整步历史，重开重新建立棋盘。
- 死区22%/16%、四向吸附滞回、触点归属沿用已有行为。未增加加速档、滑动自由移动或修改关卡解法。

已测时间轴与图形证据见 [v0.3独立审查](../../production/qa/v0.3/motion-review.md)。固定步长采样与录制用于检查时间轴和画面，不能当作设备延迟、帧率或真人手感结果。

## v0.4 跨帧余量与吞食（2026-09-30）

- 正常帧 `delta <= 0.08` 秒保留跨过当前整轮动画边界的时间余量，接续方向在同帧推进相应视觉比例。每帧最多接受一次新逻辑步；超过80ms的异常帧不追补余量。释放后不启动新动作。
- 食物在下一格时立即开始张嘴，100ms内张至大开；接触阶段（主动步75%）世界食物移除，食物副本从原目标坐标缩入口内95ms，随后闭嘴、轻咀嚼，恢复闭嘴。独立三张口型保留共同眼睛/角锚点；头部和吞入路径跟随朝向，口型计时不增加输入锁定。
- `frame_probe.gd` 为debug版本的可选诊断；仅在 `user://qa/frame-probe.enabled` 存在时启用，记录process/present计数、最大delta与棋盘绘制时间。无生产界面、用户数据或自动网络上传。诊断结束移除标记，重新启动回到默认关闭状态。
- 性能验收分别采样初次资源生成、持续运动与空闲；混合两秒窗口只作为混合统计。目标Android环境须测绘制开销、看原生录像，不能用桌面帧录或计时断言代替。

变帧调度及口型证据见 [v0.4独立审查](../../production/qa/v0.4/input-review.md)。

## v0.5 当前输入与 UI（2026-09-30）

用户确认移动流畅度后要求手柄式十字方向键；`direction_pad.gd` 替代活动入口的 `virtual_stick.gd`，方向按钮采用离散矩形命中，不再使用径向死区和跨轴滞回。四键共享一条原生触摸/鼠标路由，触摸模拟鼠标过滤、触点归属、取消和左右手布局见 [方向键契约](dpad-contract.md)。`main.gd` 接收同样的 `direction_changed` 信号，MOVE_SECONDS、长按时钟、变帧余量与吞食调度不变。

`ui_skin.gd` 缓存 ImageGen 烘焙釉面图册与九宫格资源；方向键有专用方形三态，主/次按钮与面板共用配色和光源。布局扩大底部按键区，棋盘和提示条避开触达区域，首页、关卡、HUD、暂停和设置统一材质。素材不在运行中逐像素生成或连续绘制 AA 圆。版本 v0.5.0，Android versionCode 6。
