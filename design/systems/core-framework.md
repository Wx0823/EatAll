# EatAll 核心框架提案 v0.1

状态：设计提案，待用户确认后进入实现。2026-09-29。

## 依据与授权

用户要求根据视频分析设计休闲游戏框架，美术偏欧美，并明确“优先竖屏，虚拟轮盘操作方向”。本轮交付设计文档；平台发行渠道、引擎、具体画面技术和以下规则细节仍是团队建议。

参考画面能支持：蛇形身体、吃果增长、支撑与整体下落、缺口绕行、失支掉落。原作引擎、精确增长单位、自碰规则、胜利条件和撤销机制不能从已分析片段确认。本文制定的是 EatAll 候选规则，不是原作源码还原。

## 体验与核心循环

一句话：用不断长大的身体当桥梁，在小巧的竖屏棋盘中吃光点心，稳稳钻进出口。

目标体验是“看懂局面 → 试一步 → 发现身体的用途 → 解开小难题”，依靠规划获得满足，避开反应速度压力。轻松、滑稽、亲切的欧美卡通表达必须服从棋盘清晰度。

关外：选关/继续 → 进入短关 → 完成解锁下一关。关内：观察果实与支点 → 四向移动和增长 → 重力重新结算 → 调整路线 → 吃完指定食物并到达出口。失败或走进死胡同可随时撤销或重开。

## 最小交付范围（建议）

- 12 个短关、1 个主题、1 个可操控角色；前两关教学，中段组合练习，末段检验。
- 固定侧视的二维网格逻辑，竖屏完整显示单关棋盘；不滚屏、不依赖镜头追踪隐藏支点。最终渲染方法由技术与美术方案确认。
- 必要界面：开始/继续、选关、关内食物进度、出口状态、撤销、重开、暂停、过关与失败反馈。
- 本地保存解锁进度、当前关与基础设置；具体是否恢复局中状态在实现方案中明确。
- 无跳跃、计时、体力、分数排行、广告、付费、养成、移动平台和随机地图。后续增加系统需要单独评估，不计入首版承诺。

## 唯一规则基线 EA-R0.1（均为提案）

地图使用整数网格，x 向右、y 向下；身体是头到尾有序、正交相邻且互不重叠的坐标。角色至少两格。地形、果实、刺、出口和身体分别记录，不把视觉弯曲当作碰撞形状。

| 编号 | 规则 | 边界与反馈 |
|---|---|---|
| R01 移动 | 轮盘方向映射上、下、左、右，每次有效动作头进入相邻一格，身体依次跟随 | 无斜移、跳跃或直接180度掉头；无效动作只给阻挡反馈，不改变状态或生成撤销记录 |
| R02 增长 | 主动移动的头进入果实格时移除果实，保留旧尾，长度加1格 | 其余正常动作移除旧尾；重力经过或停在果实格不吃，不增长 |
| R03 自碰 | 不能进入本步结算后仍被身体占用的格子 | 非增长时可进入本步即将腾空的旧尾，但仍需满足禁止直接反向规则；不是禁止一切回到尾格 |
| R04 支撑 | 任一身体格正下方一格是实体墙/地面，则整条身体得到支撑 | 身体、果实、出口和独立刺物件不提供支撑；侧面贴墙和顶住天花板也不算支撑 |
| R05 重力 | 无支撑时，保持身体形状，每次整体向下平移一格，直到获得地形支撑或失败 | 重力优先完成，期间不能移动；墙地面占据一个实格，无半格悬停，不模拟重量/重心/扭转 |
| R06 危险 | 任意身体格与刺重合或离开棋盘边界时失败 | 每个主动移动及下落单格之后检查，防止穿过危险；底部空白边界不是地板 |
| R07 出口 | 所有果实吃完后，完成重力结算且落稳，头位于出口格即胜利 | 尾部进入不胜；经过出口但继续下落不胜；剩余果实时出口可穿过但不触发，视觉显示未就绪 |
| R08 撤销 | 恢复上一次有效主动动作之前的完整稳定状态 | 包含身体顺序、果实、目标状态；该动作导致的全部下落一并撤回，失败后也可撤销，无限次数 |
| R09 重开 | 恢复该关初始稳定状态并清空该关撤销历史 | 不清除已经完成的关卡记录；不可从初始状态撤销到上一关 |

建议地图约束：出生必须稳定、安全；果实、出口和刺不可与实体地形重叠；果实与出口/刺互不重叠；初始身体不得压住果实或出口；刺是空格中的危险物件，其下可以有实体地面。关卡工具在实现阶段检查这些约束。

### 一次动作的严格顺序

1. 仅稳定、可操作状态接受方向。计算下一头格，先排除直接反向。
2. 判断下一头格是否存在果实，得到本步是否增长；据此判断实体地形与保留身体格的碰撞。非法动作结束，保持原状态。
3. 为合法动作保存动作前快照；插入新头；有果实则删除果实并保留旧尾，否则删去旧尾。
4. 检查刺与棋盘边界；触发则失败，不继续结算出口。
5. 检查支撑；无支撑则整体向下平移一格并检查危险/边界，循环到落稳或失败。下落不收集果实。
6. 落稳后，检查“剩余果实为0且头在出口”；满足则成功，否则回到可操作状态。
7. 画面按结算事件播放移动、吃果、下落和成功/失败反馈。动画不引入额外碰撞，也不让轮盘积压多个动作。

例：三格身体向果实移动后变成四格；接下来的普通移动仍是四格。若头和中段悬空，但尾格下面有地面，整体不落；尾格前移离开地面时才开始下落。

果实被身体遮挡时仍保留描边/轮廓提示，尤其是重力落到果实格后，不得让玩家误认为已经收集。未吃的食物计数必须与逻辑一致。

## 输入与状态机边界

已定交互方向为竖屏虚拟轮盘。建议四向吸附；首次有效指向触发一步，长按逐步重复，松手即停；动画和重力结算时不积压操作。死区、重复间隔、跨方向滞回等以程序稿为单一参数来源，初值需要真机测试，不能当作用户要求。

`加载 → 稳定待输入 → 主动移动 → 重力结算 → 稳定待输入 / 成功 / 失败`。

- 无效方向停留在稳定状态；不扣资源，不进入失败。
- 暂停保留当前逻辑状态且停止接收移动；失焦清空轮盘持续输入，恢复后重新拨动。
- 失败态保留现场，突出失败位置；可撤销或重开。成功态停止移动，提供下一关和重玩；已解锁进度幂等保存。
- 动画中暂停时，取消未播完表现并显示本回合已经结算的稳定或终局状态，不回退动作；撤销恢复有效动作前快照，重开恢复本关初始快照。三者都禁止显示半个状态，程序可以用统一命令入口保证一致。
- 到达死胡同但未碰危险不自动判负；撤销是主要恢复手段。首版不承诺自动死局检测或全局提示求解。

## 跨角色验收

程序和测试必须覆盖：果实增长1格；旧尾合法进入与增长时自碰区别；直接反向阻挡；仅尾部支撑；贴墙不支撑；下落经过果实不吃；刺逐格检查；出口需落稳与全收集；失败后一次撤销恢复整步；无效输入不占撤销；长按不积压动作。

关卡以本规则编号引用，不自行增加例外；难度由规划和身体形状产生。美术必须让实体地形、空隙、刺、剩余食物、出口开闭和头尾方向一眼可分；装饰不能伪装成支点。是否好玩、触控是否舒服和12关的真实时长均需原型试玩验证。

## 核心取舍与待确认

团队推荐先做“固定网格 + 整体重力 + 12关”以便验证空间谜题，保留欧美卡通的夸张表情与柔软动画。全食物出口条件强化主题并减少通关歧义；代价是少了选择性收集路线，需在试玩中观察是否造成回头补捡的拖沓。用户确认该框架后再实现；平台渠道和技术栈由主理人汇总必要选择，不逐个规则数值追加审批。
