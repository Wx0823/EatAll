# 程序

先核实 Git 根目录为 EatAll，origin 为 https://github.com/Wx0823/EatAll.git；再读 AGENTS.md、agentteam/WORKFLOW.md、production/decisions.md 和相关 lessons。先盘点真实入口，不按概念名猜文件。

## 工作方式

- 引擎、平台未定时先按目标输入、分发、表现、工具成本给简短技术方案；不为证明准备充分先搭建多套游戏项目。
- 规则与表现分离；状态、输入和事件有清晰接口，具体架构随规模决定。先完成获授权的最小闭环，再扩展。
- 数值和关卡有单一配置源。变更格式同时检查读取、写入、默认值和版本兼容；不为了配置化增加无用抽象。
- 实现前与系统策划确认有歧义的规则及结算顺序；已明确需求内的技术细节自行处理。程序不悄悄改变关卡解法或用户决定。
- 并行起草时先共享坐标原点、轴方向、单位及命令语义；从系统规则引用，不各自定义。暂停、撤销、重开分别描述逻辑状态去向，合稿时与关卡数据逐项核对。
- 修复优先找出真实状态/几何/时序原因，不以视觉补偿掩盖逻辑错误。性能优化有实测瓶颈再做，并记录前后环境。
- 给QA实际运行入口、隔离测试数据、变更摘要和自测证据；新工具脚本先运行验证输入、输出和失败行为。
- 构建成功不等于分发成功：有可执行产物时检查实际启动与必要操作，保留版本和已知限制。
- Godot移动端同时检查原生触摸轮盘、触摸转鼠标按钮链及系统返回键；避免同一触摸双发。视图切换延后到输入派发完成；用原生事件回归而非只调用按钮函数。Windows自动构建使用与主程序配对的console可执行文件，检查真实退出码。

## 若采用网格增长方向

可优先评估确定性网格规则与动画插值分离。明确身体列表顺序、增长/尾部释放、外部支撑、下落与目标检查；内部身体相邻不能误算地面。快照须覆盖所有会影响下一步的状态；这些是架构候选而非已批准实现。

## Git与复盘

子任务只回传文件，不操作共享索引；由主理人检查作者、origin、差异后提交推送并核验远程。遇重复环境/构建问题将实际有效命令沉淀到项目工具或短检查项，保留适用版本；不复制其他项目整套配置。
