# EatAll 团队工作流

## 角色与文件所有权

| 角色 | 何时调用 | 默认负责的产物 |
|---|---|---|
| [系统策划](eatall-system-designer/SKILL.md) | 核心循环、规则、资源与数值、跨系统一致性 | `design/systems/` |
| [关卡策划](eatall-level-designer/SKILL.md) | 教学、关卡结构、难度、解法与地图数据 | `design/levels/`；运行时地图数据须与程序约定 |
| [测试](eatall-qa/SKILL.md) | 验收、复现、回归、关卡可解性、交付检查 | `production/qa/`；测试代码路径派工时约定 |
| [程序](eatall-engineer/SKILL.md) | 技术方案、实现、工具、构建、性能 | 实际代码/构建目录，确定技术栈后记录 |
| [美术](eatall-art/SKILL.md) | 风格提案、信息可读性、资产规格、制作与实机审稿 | `design/art/`；资产源文件/导出目录派工时约定 |

主理人为当前负责整合的助手，不额外创建常驻角色。共享决定由主理人维护；同一文件同一时间只有一个写入者。上述未存在的路径是未来输出约定，不得当作已有输入读取。

## 最短执行路径

1. 核实工作根目录和 origin，读 AGENTS.md、production/decisions.md，按关键词查 lessons.md。先盘点真实文件，再引用具体输入。
2. 明确本次交付及现有授权。用户明确交办的范围直接执行；不将空白决定、默认建议或专家意见当作用户决定。新游戏方向和技术栈先形成简短可比较方案，由用户选择；已明确范围内的常规细节自行处理。
3. 只启用相关角色。复杂任务可按独立文件分工；跨系统接口先由系统策划和程序对齐，关卡与美术按同一版本制作。缺关键信息时继续不依赖该信息的工作。
4. 制作与验证同步进行。程序自测与测试角色验收分开；独立测试不可只复述程序结论。美术检查实际运行画面；概念图不能替代实机验收。
5. 整合后检查变更和必要验证，主理人提交并推送 EatAll，核实远程包含提交。交付列出结果、证据、未覆盖范围及必要下一步。
6. 有实际教训才做复盘：更新 lessons.md，并把预防措施落实到相关技能、检查项或有价值的回归。无新问题不强制造报告。

## 派工与回传

派工信息按复杂度裁剪，可直接放在子 agent 消息中，无需为每次任务创建文档：

```text
目标与授权范围：
输入：真实文件路径、规则版本或具体用户要求
输出及独占文件：
依赖与禁止触碰的共享文件：
验收：可观察结果、必要证据
停止条件：完成；或具体依赖阻塞时回报
```

回传实际修改、验证命令/结果、风险、待整合事项。主理人核对证据再采纳结论，不以成员名称代替验证。只能访问本轮授权资源；不自动另建用户聊天或发送外部消息。

## 验收与效率

- 状态：待决定 / 可执行 / 进行中 / 待整合 / 已验证 / 阻塞。验收结论：通过 / 有保留 / 不通过；写清适用范围。
- 小改动只跑受影响的检查。规则、保存、输入、碰撞等关键路径做实际行为验证；不为措辞、标题和可逆文档变更堆砌镜像测试。
- 证据区分：设计推演、代码检查、自动测试、实际运行、真实玩家体验。没有运行不能报运行通过；未测性能不报帧率。
- 相同失败没有新证据时不盲目重试；先核对环境/输入/版本，再改变一个变量定位。保留有意义的失败证据，不反复生成重复报告。
- 每个事实维护一处：决定在 decisions.md，机制在系统规则，关卡只引用机制，美术只维护表达和规格，测试引用验收条件。

## 自行改进的闭环

仅在实际任务结束或发现可复用问题时执行，不表示后台常驻运行：

`实际问题 → 最小证据 → 原因及置信度 → 小范围修正 → 针对性验证 → 下一次使用时确认效果`

- lessons.md 每条写触发场景、现象、原因、措施、证据、遗留和状态。连续尝试归为同一事件。
- 先判断是产品、测试夹具、工具、协作还是判断错误；不能为了测试变绿而削弱正确验收。
- 反复出现的操作可提取脚本，先证明其输入输出和失败行为；单次事件优先用短检查项。
- 修改技能保留适用范围、更新理由和验证结果。新规则不得扩大项目授权、制造额外审批或引入其他项目要求。
- 有证据证明规则无效/重复时合并或删减，并保留修订理由；经验数量不作为效率指标。
- 效果使用真实的重试次数、返工次数或完成耗时比较，注明样本和环境；没有可比数据标为待验证，不编造提升百分比。
- 复盘修正经主理人自查并提交；高风险可独立复核。明确自查或独立复核，不为记录自身SHA无限追加提交。
