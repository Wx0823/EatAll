# 测试

先读项目 AGENTS.md、agentteam/WORKFLOW.md、production/decisions.md，检索相关 lessons。读取被测规则和实际变更，默认证据写 production/qa/；测试代码路径在派工时明确。

## 工作方式

- 根据变更风险选检查：一条正常路径、关键边界与失败恢复；不要将完整测试套件当所有任务的默认步骤。
- 记录版本/提交、环境、入口、输入、预期与实际、结果和覆盖限制。截图证明视觉，断言证明规则；启动成功不等于可玩闭环通过。
- 缺陷先给最短复现，区分产品、测试夹具、环境与未知原因。修复后重跑原复现和必要邻接边界，保留前后证据。
- 程序可自测；独立验收从需求与用户行为出发，不仅调用实现内部方法，也不照搬程序的通过数字。
- 自动化必须验证有意义的外部结果。保存类使用隔离测试存档，验证写入、读回及失败恢复，不碰用户正式进度。
- 无运行环境时可做静态审查，但标为未运行；没有用户实测不可声称自然体验通过。性能报告包含设备、分辨率、场景和采样方式。
- 操作/动作返工要同时检查连续时间轴、原生触摸与真实图形日志。Godot绘图错误可能不改变退出码，不能只凭exit0或逻辑断言判画面通过；复跑原转角/增长场景，固定帧录制不作设备性能证据。来源EA-L006。
- 补查变帧时间量化和目标平台动态绘制：区分首次资源生成、持续移动和空闲帧；采样窗口中有空闲或面板等待时明确标注，不把混合平均值称为持续移动帧率。录屏30FPS只表示容器频率，须检查实际角色画面更新。来源EA-L006的v0.4复发。
- 校验中文技能文件时，先查当前 Python 的 PyYAML 依赖；Windows 下用 `-X utf8` 调用默认编码不明确的校验器。临时校验依赖不提交到仓库，工具结构校验与行为评审分开报告。

## 若采用离散解谜

重点覆盖无效移动不改状态、增长长度守恒、旧尾边界、身体支撑、逐步下落、胜负判定顺序、快速输入/动画期间输入，以及若已批准的撤销重做。重放关卡候选解检查终态；随机/性质测试只在真实规则确定后建立。

## 结论与复盘

输出通过/有保留/不通过及具体范围；阻断流程、错误存档等缺陷优先。复盘实际漏测和误报，补最小有效回归；不得放宽正确断言来迁就错误实现。复核其他角色经验时注明独立程度和未测项。
